# 设计：嗅探资源在页面内的定位与叠加层

日期：2026-11-26
状态：设计稿，未实现
范围：`sniffer_extension/`（injected.js / content.js / background.js）、`YtDlpWeb/server.py` 的条目字段、`YtDlpGUI/ui/js/sniff.js`
前置约束：本设计需要改动 `sniffer_extension/` 与 `YtDlpWeb/server.py`，超出 `AGENTS.md` 现行的「不可改动」范围，需先取得豁免

---

## 1. 目标

嗅探到资源后，除了在列表里分类展示，还要回答「它在页面哪个位置」：

1. 视频 / 图片在页面上被高亮框标出；
2. 框的右上角有下载按钮，点击即进入现有下载流水线；
3. 桌面版列表里点某一条，页面能滚到对应元素并闪烁提示。

非目标：不做视频内画面的元素识别（不判断「画面里第几个人」），不做跨标签页聚合，不做 DRM 内容定位。

---

## 2. 定位能力分档

「资源 URL → DOM 元素」不是天然的一一对应，尤其播放器用 MSE 时 `video.src` 只是 `blob:`。按资源怎么播放分四档，覆盖率依次下降：

| 场景 | 定位手段 | 粒度 | 覆盖率 |
| --- | --- | --- | --- |
| `<img>`、`<video src=mp4>`、`<audio>`、`<source>` | `currentSrc` / `src` 直接匹配 | 元素 | 接近 100% |
| hls.js / dash.js（`src` 是 `blob:`） | 主世界钩住 `URL.createObjectURL` + `MediaSource.addSourceBuffer`，用「哪个 SourceBuffer 最近在 appendBuffer」反查元素 | 元素（一元素对多流） | 90% 以上 |
| 只有网络层、没有页面钩子 | 时间相关性 + 可见面积 + `currentTime` 是否在走，加权打分 | 元素（可能多候选一起标） | 60–80% |
| canvas / WebGL 自绘播放器、closed shadow DOM | 无 | 无 | 0 |

覆盖率是工程经验估计，需按 §8 的清单实地校准之后再写进 README。

---

## 3. 三个关键决定

### 3.1 按元素聚合，不按资源聚合

**决定**：一个播放器元素只出一个高亮框、一个下载按钮；点开按钮展开该元素的全部流（1080 / 720 / 纯音频）。

**理由**：hls.js 的一个播放器通常对应 1 条主清单 + N 条码率子清单 + 几十个分片。若按条目逐个画框，同一个 `<video>` 上会叠出几十个按钮，既点不中也没有意义——用户要的是「下这个视频」，不是「下第 37 号分片」。

**被否决的做法**：每个嗅探条目一个按钮（视觉叠爆）；只画最高码率那一帧（用户无法切换音轨/码率）。

**实现要点**：
- 条目侧新增 `element_hint = { frame_id, path, tag, width, height }`，同一 `path` 的条目归到一组；
- 分组键用 `frame_id + path`，不用 URL；
- 按钮文案展示组内条目数，例如「下载 · 3 条流」。

**验收判据**：在 hls.js 站点上，一个播放器只出现一个框；展开后条目数与嗅探列表里同元素的条目数一致。

### 3.2 单层 overlay，不往页面里插节点

**决定**：用一个 `position: fixed` 的容器统一绘制所有高亮框和按钮，容器 `pointer-events: none`，只有按钮 `pointer-events: auto`。

**理由**：逐个元素包裹（`position: relative` 的 wrapper）会改动页面布局，直接被站点 CSS 命中；插入的节点会被部分站点的 MutationObserver 当垃圾清掉；清理时要逐个删，容易漏。单容器方案对页面 DOM 零侵入，清理只删一个节点，且天然不受 `overflow: hidden` 裁剪影响。

**被否决的做法**：给每个媒体元素外包一层 wrapper（改布局、易被清）；用 `outline` 直接改元素样式（会被站点样式覆盖，且无法放按钮）。

**实现要点**：
- 容器 `z-index` 取页面最大值之上，`inset: 0`；
- 每帧用 `requestAnimationFrame` 合并重算，配合 `ResizeObserver` 与 `scroll` 被动监听；
- 进入全屏时把容器重新挂到 `document.fullscreenElement` 下，退出时挂回 `body`，否则框不可见；
- 播放器原生控件条会压住右上角按钮，按钮按控件高度下移（默认 40px，可配）；
- 隐藏容器用 `display: none`，不要用 `visibility`（后者仍参与合成层）。

**验收判据**：打开/关闭叠加层后，页面 `document.body` 的子节点数量不变（除容器本身）；全屏下框仍可见；滚动时框跟随无肉眼延迟。

### 3.3 存选择器，不存坐标

**决定**：条目里存「帧路径 + 选择器路径」，点击定位时现场 `getBoundingClientRect` 重算，不落库任何坐标。

**理由**：SPA 一重渲染、图片懒加载撑开高度、用户缩放或改窗口大小，之前算的坐标必然失效。存坐标等于把一次性快照当长期事实，最终表现为「点了定位，框画在空白处」。选择器路径加现场重算，代价是一次 DOM 查询，换来的是不会错位。

**被否决的做法**：嗅探时记录 rect 并随条目上报（列表一刷新就过期）；存元素索引 / `data-*` 标记（重渲染后失效，且污染页面属性）。

**实现要点**：
- 选择器路径由 `tagName + nth-of-type` 逐级拼接，遇到 `id` 提前收敛；同名兄弟过多时退回「最近的有 id 祖先 + 相对路径」；
- 路径失效（元素已不在）时明确提示「元素已不在页面（可能已重渲染）」，不静默失败；
- 跨帧定位不在父帧换算坐标：每帧各自在自己的文档里画自己的框，坐标天然正确；「滚动到元素」用 `postMessage` 逐级上抛，由各帧自己 `scrollIntoView`。

**验收判据**：定位后手动触发页面重渲染（切换路由再切回），再次定位仍能落在正确元素上；iframe 内的元素定位后滚动位置正确。

## 4. 明确的能力边界

真正做不到的只有三类，其余都是「能做但不完美」：

| 类型 | 说明 |
| --- | --- |
| canvas / WebGL 自绘播放器 | 页面里没有 media 元素，只有一块画布，没有可标的目标 |
| closed shadow DOM | 进不去；`open` 的可以递归进去 |
| DRM 内容 | 本就不支持下载，定位没有意义 |

两个「能做但不完美」：

- **全屏**：必须把 overlay 重挂到 `fullscreenElement`，否则框消失；原生控件条会遮住右上角按钮，需下移。
- **懒加载图片**：元素尚未渲染时条目已存在，定位会失败，需给出明确提示而不是无反应。

## 5. 前提与依赖

1. **`document_start` 注入**：MSE 钩子必须抢在页面脚本之前打。扩展已具备（`injected.js`，`world: MAIN`，`run_at: document_start`）；内嵌 WebView2 目前没有公共的早期注入 API（只能走内部字段 `.gui.webview.CoreWebView2` 或 `REMOTE_DEBUGGING_PORT` + CDP）。**因此定位先做扩展侧，不依赖内嵌浏览器。**
2. **条目 schema**：需要先有 `cat`（video / image / audio / stream / other）与 `entry`（extension / embedded）两个字段，否则不知道哪些条目该画框。当前 `kind` 字段语义混用（扩展上报 mime、`sniff_download` 里写 `"media"`），且被截断到 16 字符，需一并收敛。
3. **命令通道**：桌面版「点条目 → 页面定位」目前只能借扩展 1.5 秒一次的轮询响应下发，延迟可接受；不要在这条通道上做悬停高亮。

- 此前讨论中给过 6–9 人日，上沿本次上修，原因是把测试夹具与跨帧定位单独列了出来。

## 7. 落地顺序与依赖

1. 先定 `cat` / `entry` 与 `element_hint` 三个字段（与「分类展示」共用一次 schema 改造）。
2. 做元素映射 + overlay + 定位闪烁（最小切片），在扩展侧跑通。
3. 补 MSE 钩子与多流聚合，把覆盖率抬到 90% 以上。
4. 内嵌浏览器接入时复用同一份 overlay 与钩子，不重写。

与整体优先级的关系：本项不依赖下载引擎与队列，可与「直链分段引擎」并行；但排在内嵌浏览器之前，因为它先解决「能不能定位」，内嵌只解决「在哪儿定位」。

## 8. 待实地校准清单

实现前用三个站点各花十分钟验证，比继续推演准：

| 待验证 | 站点类型 | 看什么 |
| --- | --- | --- |
| 直链视频 | 原生 `<video src=mp4>` 的站点 | `currentSrc` 是否等于嗅探到的 URL |
| MSE 视频 | hls.js / dash.js 的站点 | 钩子能否拿到 `createObjectURL` 与 `appendBuffer` 的时序 |
| iframe 播放器 | 播放器嵌在跨域 iframe 的站点 | 定位与滚动是否在正确的帧里生效 |

验证结论回填本文件 §2 的覆盖率一栏，再决定是否值得做 MSE 钩子。
