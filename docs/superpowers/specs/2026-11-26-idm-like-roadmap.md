# IDM 式下载能力路线图

- 日期：2026-11-26
- 状态：方向已认可；A（多任务队列）详细设计进行中
- 背景：aria2c 多连接分段与断点续传已具备（`runtime/aria2c.exe`，2026-11-26 实测通过）。
  本路线图补齐三块能力：任务队列、浏览器接管任意下载、网页浮动下载面板。
- 非目标：IDM 全量功能（站点抓取器、分类管理、计划任务、系统级下载接管）。不做照搬。

## 总览

| 子项目 | 目标 | 依赖 | 规模 | 风险 |
|--------|------|------|------|------|
| A 多任务队列 | 并发下载、排队、暂停/继续/取消、按任务日志与历史 | 无 | L | 高（动单任务核心边界） |
| B 浏览器接管任意下载 | 普通文件一键/自动交给 aria2c，含动态分段 | A | M | 中 |
| C 网页浮动下载面板 | 页内浮层提示可下载内容并提交队列 | A、B | M | 中 |

动态分段不单独立项：aria2c 本身即动态分段（`-x 16 -s 16 -k 1M`，可调），
B 的直链通道复用它，队列侧增加「连接预算」控制总连接数。

## A. 多任务队列

### 目标
- 同时进行 N 个下载任务（默认 2，可配置；0/负数视为不限制需另行讨论）
- 任务状态机：排队 → 下载中 → 完成/失败/已取消；支持暂停与继续
- 每个任务独立的进度、速度、日志、输出目录、历史记录
- 扩展（嗅探页/下载本页）任务与桌面任务进入同一队列

### 现状与需要拆掉的单任务假设
- 桌面单槽闸门：`YtDlpGUI/host.py` 的 `_reserve`/`task_kind`/`dl_urls`/`proc`/`pstate`
- 扩展服务单任务执行器：`YtDlpWeb/server.py` 的 `Runner` 单槽与 `TASK_SINK` 单任务镜像
- 播放态单份：`PLAY_STATE`（边下边播同一时刻仅一个）
- 历史单条记录、单份进度条与日志面板

### 主要改动面
- 新增任务对象与队列调度器（任务快照含 cfg/urls/outdir/source/状态/进程/日志环形缓冲）
- host：状态与自愈阶梯按任务维度；单任务字段保留为「当前任务」兼容层
- server：扩展任务投递到队列并返回 `task_id`；旧接口字段只增不删
- UI：任务列表（状态/进度/速度/暂停/继续/取消）+ 按任务查看日志
- 播放态：同一时刻只允许一个任务边下边播，其余置灰并说明

### 里程碑
1. 队列内核（无暂停）：任务模型、调度器、并发上限、状态机单测
2. 暂停/继续/取消：停进程树保留 `.part`，继续时重建命令续传（URL 过期时提示重新解析）
3. UI 任务列表与日志切换；历史按任务记录
4. 扩展任务并入同一队列，旧版扩展接口兼容
5. 自愈阶梯、边下边播、嗅探联动回归

### 验收要点
- 3 个真实链接并发，互不阻塞，进度/日志各自正确
- 暂停 ≥5 分钟后继续，`.part` 续传成功（含 aria2c 分段场景）
- 扩展一次提交 2 个任务时排队而非 409 拒绝
- 单任务边下边播行为不回归

## B. 浏览器接管任意下载

### 目标
普通文件（zip/pdf/安装包等）一键或自动交给 aria2c，多连接动态分段。

### 主要改动面
- 桌面「直链通道」：HEAD 探测 → aria2c（携带 UA/Referer/Cookies）→ 失败降级 yt-dlp generic
- 扩展显式接管：右键菜单/浮层「用 aria2c 下载此链接」
- 扩展自动接管：`downloads.onCreated` 拦截（需新增 downloads 权限、用户重新确认），
  或 webRequest 观察后提示，不静默取消浏览器自身下载
- 安全边界：仅 http/https；拒绝 file/UNC；内网地址标注提示
- 连接预算：并发任务数 × 单任务连接数设上限，避免打爆带宽与目标站点

### 里程碑
1. 直链通道 + 粘贴 URL 可用（不依赖扩展）
2. 扩展右键显式接管
3. 自动接管与 service 字段兼容（`sniff_rules.js` 仍为唯一真源）

## C. 网页浮动下载面板

### 目标
网页右下角浮层「发现视频/文件」，点开直接提交队列。

### 主要改动面
- content script 浮层（Shadow DOM 隔离），复用 `sniffer_extension/sniff_rules.js` 判定
- 同页去重与频控、关闭记忆
- 内嵌浏览器侧沿用桌面嗅探页，顺带完成原 P2 DOM 补扫
- 依赖 B 的文件识别与 A 的队列提交

### 里程碑
1. 媒体项浮层提示与一键提交
2. 普通文件项并入（B 完成后）
3. 去重/关闭记忆/回归

## 贯穿事项

- 兼容：`YtDlpWeb/server.py` 字段只增不删；扩展升级需重载；旧桌面与新扩展可共存
- 测试：队列状态机单测；暂停续传真实网络实测；扩展冒烟更新；真实入口 UI 复测
- 提交政策：未经用户明确要求不提交、不推送
- 节奏：A 完成即可日常使用；B 完成后具备「像 IDM」的接管体验；C 为体验层

## 决策记录

- 2026-11-26：用户认可 A→B→C 顺序；动态分段并入 B；队列优先于浏览器接管。
