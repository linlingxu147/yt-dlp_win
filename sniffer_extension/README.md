# yt-dlp 网页视频嗅探扩展

把 FileCentipede 的视频嗅探原理移植到本项目：**浏览器扩展嗅探 → 本机 Web 服务（server.py）→ yt-dlp 下载**。

对应关系：

| FileCentipede | 本项目 |
|---|---|
| 扩展 content_injected.js（页面钩子） | `injected.js`（XHR / fetch / JSON.parse 钩子） |
| 扩展 background.js（webRequest 嗅探） | `background.js`（webRequest 嗅探 + 端口发现 + 提交） |
| 悬浮视频条（content_medias.js） | `content.js`（聚合去重 + 悬浮条 UI） |
| ws://127.0.0.1:10111/gloryhole | `POST http://127.0.0.1:8765-8775/api/sniff` |
| filec.exe 下载核心 | `server.py` + `yt-dlp.exe` |

## 嗅探的三个来源

1. **网络响应**（后台 webRequest）：状态码 200/206 且 `content-type` 为 `video/*`、`audio/*`、HLS/DASH 清单，或 URL 后缀为 mp4/m3u8/ts/m4s/flv/mpd 等
2. **页面请求钩子**（注入页面世界）：拦截 XHR / fetch 响应正文识别 `#EXTM3U`（HLS）与 `<MPD`（DASH），钩住 `JSON.parse` 挖接口返回里的媒体地址
3. **页面元素**：扫描 `<video>/<audio>` 的 src 与 `<source>`（含 iframe 内的元素，转发到顶层汇总）

## 共享嗅探规则

`sniff_rules.js` 是扩展与桌面版内嵌浏览器的唯一规则源：MIME / 后缀、清单 / 分片、音频单轨、
URL 清洗都在这里。`background.js` 用 `importScripts` 加载，`content.js` 由 manifest 先加载；
桌面的 `sniff_rules.py` 读取同一份 `RULE-SOURCES` JSON 表，不复制第二份正则。

改规则只改 `sniff_rules.js`，然后到扩展页点「重新加载」并刷新页面。

## 使用步骤

1. **启动服务**：开着 **桌面版**（`YtDlpGUI\启动.bat`）即可——它默认内嵌本机服务，右上角会显示「扩展服务：127.0.0.1:8765」；也可以双击 `YtDlpWeb\启动.bat`（或 `python YtDlpWeb/server.py`）用独立模式。扩展会自动在 8765-8775 端口范围内发现服务
2. **安装扩展**：Chrome/Edge 打开 `chrome://extensions`（Edge 为 `edge://extensions`）→ 打开「开发者模式」→ 「加载已解压的扩展程序」→ 选择本文件夹（`sniffer_extension`）
3. **刷新页面**：装好扩展后，**已打开的页面必须按 F5 刷新**，内容脚本只在页面加载时注入
4. **日常使用**：在任意视频网页播放视频，右下角出现「▶ 嗅探 (N)」悬浮条 → 点开 → 选择条目点「下载」→ 进度直接显示在悬浮条上，文件落在 `downloads` 目录

## 看不到悬浮条？按顺序排查

1. **改过代码/刚加载扩展**：到 `edge://extensions` 找到本扩展，点「重新加载」，再回页面按 F5。未打包扩展的内容脚本会被浏览器缓存，改文件后不重载不生效
2. **页面是不是刚装的扩展打开的老标签页**：装扩展前就开着的标签页不会自动注入，刷新即可
3. **页面类型**：`edge://`、`chrome://`、扩展商店、PDF 阅读器、`file://` 本地文件都不注入内容脚本，悬浮条不会出现
4. **是本机服务端口**：`127.0.0.1:8765~8775` 上不显示悬浮条（那是 yt-dlp 服务自己的接口，嗅它没有意义）；其他本地端口正常显示
5. **被站点浮层遮挡**：点浏览器工具栏上的扩展图标，可直接唤出嗅探面板（无需悬浮条）
6. **扩展是否启用**：`edge://extensions` 里确认开关是开的，没有「此扩展程序已停用」的提示；开启开发者模式后 Edge 重启可能停用未打包扩展


## 提交时自动携带的凭据（绕过防盗链）

- **Cookie**：用 `chrome.cookies` 读取当前页/媒体域名的全部 cookie（含 httpOnly）。
  **直链和「下载本页」都会带**；服务端写成 Netscape 临时 cookies.txt 交给 yt-dlp，
  任务结束或提交被 409 拒绝时自动删除
- **Referer**：当前页面地址（下载本页没填时默认用页面 URL）
- **User-Agent**：当前浏览器的 UA

## 抖音链接

- 分享链接 `v.douyin.com/...`、视频页 `www.douyin.com/video/<id>`、精选/推荐页
  `www.douyin.com/jingxuan?modal_id=<id>` 都可以作为入口；`modal_id` 会被服务端自动
  归一成 `/video/<id>`。

- 抖音的页面提取需要 fresh cookies；用浮条「下载本页（yt-dlp）」会带当前页 cookies。

- 链接上右键 →「用 yt-dlp 下载此链接」
- 页面/视频上右键 →「用 yt-dlp 下载本页视频」（走站点提取器，适合 YouTube 等已支持站点）

## 「下载本页」失败（Unsupported URL）怎么办

「下载本页」只对 yt-dlp 收录的站点（YouTube、B站、Twitter 等上千个）有效。其他网站（如各类苹果CMS搭建的影视站）会报 `ERROR: Unsupported URL`——这不是故障，是 yt-dlp 不认识该站。正确做法：

1. 在页面上**播放视频**（真实地址常加密在播放器配置里，只有播放时才会请求 m3u8）
2. 悬浮条列表出现 **M3U8 / VIDEO** 条目后，点该条目的「下载」
3. 服务端会自动带上页面的 Cookie/Referer/UA 去下载合并

失败时悬浮条会直接显示下一步该怎么做的中文提示（由服务端翻译常见错误：站点不支持 / 403 防盗链 / 404 过期 / 连接被重置 / 请求被判非法 400 / DRM / 登录要求 / 地区限制 / 超时）。

## 报「连接被重置 / 10054」怎么办

```
ERROR: [generic] 1: Unable to download webpage:
('Connection aborted.', ConnectionResetError(10054, '远程主机强迫关闭了一个现有的连接。'))
```

这不是地址失效，是**对方服务器主动掐断连接**。常见成因三种：代理/VPN 不通（尤其环境变量里残留了已关闭的 `HTTP_PROXY`）、CDN 识别出 yt-dlp 的 TLS 指纹不是浏览器、IPv6 路由被阻断。

服务端现在会**自动依次换姿势重试**，不需要你手动加参数：

| 顺序 | 招式 | 治什么 |
|---|---|---|
| 1 | 直连（`--proxy ""`，绕开代理） | 代理/VPN 已关闭但环境变量还在 |
| 2 | 浏览器 TLS 指纹（`--impersonate Chrome`）+ IPv4 | CDN 按指纹拒绝、IPv6 不通 |
| 3 | Edge 指纹 + `--http-chunk-size 10M` | 对分块/连接行为敏感的边缘节点 |

每次重试都会续传（yt-dlp 默认保留已下载的分片），不会从头再来。悬浮条会实时显示「连接中断，改用…重试」。三招都失败才会判定失败，并提示你回页面重新播放（链接多带时效签名，拖久了就废）。

如果你的 yt-dlp 是旧版（缺 curl_cffi、不支持 `--impersonate`），服务端会探测出来并自动跳过指纹那两招，只保留直连与分块。

## 报「HTTP Error 400: Bad Request」怎么办

```
ERROR: [generic] 1: Unable to download webpage: HTTP Error 400: Bad Request
```

400 的意思是**服务器认为这个请求本身不合法**，不是连接断了、也不是没权限（那是 403）。视频 CDN 上最常见的两种成因：

- **Referer 是外来域名**：不少 CDN 不返回 403，而把「来源不对」直接判成 400
- **缺 Origin / Accept 这类浏览器必带头**：yt-dlp 默认只发最小请求头

服务端会自动按顺序试，不需要你改参数：

| 顺序 | 招式 | 治什么 |
|---|---|---|
| 1 | 去掉 Referer | CDN 见到外部来源直接判非法 |
| 2 | 补 `Origin`（取页面域名）+ `Accept` + `Accept-Language` | 要求同源/浏览器请求头 |
| 3 | 浏览器 TLS 指纹 + IPv4 | 前两招无效时兜底 |
| 4 | Edge 指纹 + 10M 分块 | 边缘节点对连接行为敏感 |

另外提交前会先**清洗地址**：去掉网页里粘来的零宽字符、换行，把 HTML 转义（`&amp;`）还原成 `&`——这类脏字符肉眼看不见，但对端会直接判 400。

四招都失败时说明链接本身已被页面脚本改写或时效参数过期，回页面重播、等新条目出现立刻点下载。若列表里那条地址异常短（明显缺参数），改用「下载本页」。

## 音频单轨默认隐藏

B 站等 DASH 站点会把音频单独做成一条 `.m4s`（流 ID `302xx`），它和视频轨是两条独立地址；
下载某一条只会得到那一轨。面板默认隐藏音频单轨，避免误点后只拿到音轨：

- 面板标题旁的「显示音频 (N)」开关可展开/收起，状态会记住（`chrome.storage.local`）。
- 展开后音频条目标蓝黄「音频」标签，仍可正常试播/下载。
- 识别口径与桌面版一致：`[-_]302\d{2}\.m4s`（B 站音频）或 `.m4a/.mp3/.aac/.flac/.wav/.ogg/.opus`；
  逻辑在 `sniff_rules.js` 的 `isAudio`，`audio_stream.js` 只保留旧函数名给 content 脚本用。

## 已知边界

- **blob:/data: URL 无法下载**：这类地址只存在于浏览器内存里，yt-dlp 拿不到；此时应改用「下载本页」让站点提取器处理
- **DRM 内容（Widevine 等）不支持**：地址能嗅探到，但明文流受版权保护，yt-dlp 无法也不会解密
- **单任务**：服务端同一时间只跑一个任务，忙时提交返回 409 并在悬浮条提示
- 服务只监听 127.0.0.1（本机专用），并校验 Host / Origin / Content-Type；扩展提交走 127.0.0.1

## 服务端接口（server.py 新增）

- `POST /api/sniff`：`{url, kind: media|page, referer, ua, cookie_jar, title}` → 启动下载线程
- `GET /api/sniff/log`：`{busy, done, code, prog, last_text, kind, hint, lines}` → 扩展每 1.5 秒轮询显示进度；`hint` 是失败时服务端翻译的中文提示
